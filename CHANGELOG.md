## [Unreleased]

### Changed
- Bitmap capability discovery is conservative and face-wide: every declared strike of a route must be structurally valid, one malformed unselected strike withdraws the route, and scan budgets for compressed and decoded bytes accumulate across all declared strikes while materialization applies per-strike budgets; duplicate declared strikes are rejected with the route-specific duplicate-strike failure when requested and withdraw the route during capability discovery.
- The canonical portable bitmap profile fingerprint changes: the strike token now carries the exact bit depth, so regenerate persisted profile fingerprints for every bitmap profile, including profiles whose declared parameters did not otherwise change (previously schema-1). Bitmap representation schema version 2 replaces version 1: `BitmapStrike` appends a required `bitDepth`, `BitmapLimits.maxBitmapTableBytes` becomes `maxSourceTableBytes`, and `BitmapProfile` defaults to schema version 2. Recompile consumers that construct these values, pass the exact strike bit depth (1 for the existing EBLC/EBDT monochrome route), and expect `font.unsupported-representation-profile` for version 1 bitmap profiles; existing monochrome glyph results are unchanged.
- Bitmap resource-bound breaches are now terminal instead of representation-local: a `BitmapResourceLimitExceeded` aborts the calling resolution instead of falling back to another accepted profile or font, unlike the generic `ResourceLimitExceeded` still used by the outline, SVG, and paint readers.
- The optional Apple module uses dedicated kffi CoreText bindings and Darwin system-information access instead of declaring native frameworks, symbols and layouts locally; font certification, resource ownership, budgets, cancellation and public leases retain their existing contracts.
- macOS directory capture retains existing Kotlin call defaults but appends examination/diagnostic options and cancellation parameters: recompile consumers because the JVM constructor/factory entry points changed. Captures refresh explicitly into isolated generations.
- Font captures accept a trailing optional shared cache scope; recompile JVM consumers using changed factory/constructor signatures. Existing Kotlin calls retain their defaults and CoreText retention stays disabled by default.
- Paint schema 3 appends interpolation parameters to `GlyphPaintColorLine` and `PaintGraphProfile`, and three SVG transport bounds to `PaintGraphLimits`: recompile consumers using the changed JVM constructors or generated copy signatures, handle `PathClip` and the new interpolation enums, and regenerate persisted profile fingerprints even for schema 1 or 2. Historical COLR interpolation defaults are preserved; see the bilingual font-management migration notes.
- Static COLR v1 expands paint constructors, `PaintGraphLimits` generated `copy` signatures and sealed/enum cases: recompile consumers, update exhaustive handlers, never persist enum ordinals, and regenerate persisted profile fingerprints, including schema 1. Ordinary recompiled Kotlin constructor calls retain defaults; this is not JVM binary compatibility. Empty-group rejection now occurs when constructing schema-1 `GlyphPaintIR`, not `Group` alone; see the font-management migration notes.
- FontMaterializationCachePolicy now uses structured per-face/per-catalog budgets: generated Kotlin copy/destructuring operations are source- and binary-incompatible with the former byte-only data class; migrate to perFace/perCatalog and recompile consumers that used the old generated operations. The historical byte-only constructor and getter remain available.
- `FontError.CertificateNotInLayout` extends the sealed error surface used by the new font-asset handoff route. Add an arm when recompiling exhaustive Kotlin `when` handlers; existing method and JVM signatures remain available, but an already compiled exhaustive handler can throw `NoWhenBranchMatchedException` if this new member reaches it. Existing calls do not automatically emit this error.
- Kotlin 2.4.0 → 2.4.10
- Gradle 9.5.0 → 9.6.1
- Added blocking pull request policy checks aligned with `CONTRIBUTING.md`.
- Legacy `font/` sources are retained for reference but excluded from Gradle project aggregation, API documentation, and CI.
- The documentation site now embeds the API reference for the Kalligraphie modules.

### Added
- Portable conformance now publishes a bilingual conformance matrix: the documentation states each reference platform's declared capability surface (JVM complete; Apple and Android absent for Unicode analysis, shaping and end-to-end layout, present for glyph representation variants), the comparison classes, the empty justified tolerance catalog, the six bounded divergences, and the known limitations, in English and French.
- Portable conformance now documents bounded platform divergences as explicit capability records and verifies that decoding observables are platform-invariant, so the only admissible cross-platform difference is the declared capability identity.
- Portable conformance now includes Android instrumented device tests: a Gradle Managed Device is declared for the conformance module, the portable facade is exercised on a real Android runtime, and the test task was validated on an emulator.
- Portable conformance now announces an explicit, compiled capability identity per platform and verifies cross-platform capability gating: JVM declares the complete reference surface, while Apple and Android declare Unicode analysis, shaping and end-to-end layout absent and the portable glyph representation route present.
- Portable conformance now verifies cancellation and atomicity through observable effects: a cancelled or limit-exceeded decoding operation publishes no partial snapshot or diagnostics.
- The conformance module now defines a canonical portable corpus and a reference oracle that reproduces every expected canonical envelope, with an explicit, empty tolerance catalog because decoding conformance is bit-identical.
- The non-published conformance module now carries a portable editor corpus: a scenario model, a versioned canonical observation envelope, portable decoding scenarios executed on JVM and Kotlin/Native, and capability gating that yields a deterministic absence diagnostic instead of an observation.
- Portable decoding conformance tests exercise the public facade from `commonTest` on JVM and Kotlin/Native, proving the portable text pipeline is usable without any platform type crossing `commonMain`.
- A non-published `:kalligraphie:conformance` module is introduced to host the portable conformance contract (comparison classes, canonical unit, tolerances, diagnostic comparison and capability identities) in `commonMain`, without being published to Maven Central.
- sbix version 1 colour strikes with `'png '` graphics (version 1, bit 0 of the flags field set, reserved flag bits zero) selected by the exact `ppem` with no neighbouring-size substitution, origins and advances normalized from design units to strike pixels with round-half-away-from-zero, `'dupe'` records resolved to the referenced glyph's image within the same strike, and advances resolved from `hhea`/`hmtx` without requiring `glyf`; `'jpg '`, `'tiff'`, `'pdf '`, and `'mask'` remain unsupported. When a face certifies both colour routes, CBDT/CBLC is selected deterministically and its failure is final: there is no cross-route fallback.
- CBDT/CBLC colour bitmap strikes (table versions 2.0 and 3.0, index subtable format 1, CBDT image formats 17 and 18) decoded through the bounded PNG subset to straight non-premultiplied `RGBA_8888` in sRGB, selected by the exact `(ppemX, ppemY, 32)` strike with no neighbouring-size substitution; suggested `PLTE` chunks are tolerated, ancillary chunks ignored, glyph metrics must match the embedded image dimensions, and uncompressed 32-bit BGRA data, image format 19, and vertical strikes remain unsupported.
- Straight non-premultiplied `RGBA_8888` bitmap pixels in sRGB alongside the existing `ALPHA_8` format, `FontError.BitmapResourceLimitExceeded` with a machine-readable `BitmapResourceLimit` dimension for every bitmap bound, and a bounded PNG decoder that validates declared dimensions before inflation and refuses decompression bombs, palette, greyscale, sixteen-bit, and interlaced images before publishing any pixels. This adds a member to the sealed `FontError` interface and a case to `BitmapPixelFormat`: recompile consumers with exhaustive handlers, and note that an already compiled exhaustive handler can throw `NoWhenBranchMatchedException` if the new member reaches it.
- Deterministic CPU rasterization for tests and demonstrations through `org.graphiks:raster-cpu`: coverage for outlines and paint paths, composed into non-premultiplied RGBA, normalized `ALPHA_8` strike rendering with an explicit ink, typed refusals with declared bounds, sealed coverage fingerprints on audited fixtures, and an opt-in PGM/PPM demonstration runner with a reproducible manifest. The demonstration runner now also publishes multi-script alphabet sheets (Latin, Greek, Cyrillic, Arabic, Devanagari), color sheets and a normalized EBDT bitmap strike, and real text lines composed through the paragraph facade with shaping, BiDi, and three-font fallback; composed outputs are flipped vertically for readability and every dump is double-rendered for byte-exact determinism. The same module renders the repository logo assets — a knocked-out Amiri `K` badge framed on a 512 × 512 transparent canvas for avatars and favicons, plus the Great Vibes wordmark shaped by the pinned HarfBuzz backend for the README — as light and dark transparent PNGs under `docs/assets/`, sealed by pixel fingerprints and a manifest, and regenerated by the opt-in `:kalligraphie:raster-cpu:renderLogo` task.
- Bounded JVM directory font captures and Linux/macOS system-directory providers, including standalone static TrueType and original-index TTC 1/2 faces, detached original source bytes, partial diagnostics, cooperative cancellation and independent render-resource ownership. Collections must fit their complete face count within the remaining examination budget or are rejected whole before examining a prefix; separate fully examined sources can still form partial catalogs, and the accepted-face cap applies independently after examination. Discovery checks cancellation and path bounds before lazy lookahead. CFF/CFF2, native activated registries and Windows/mobile font journeys remain unsupported. The four-target HarfBuzz JVM CI matrix also runs directory and system-catalog shaping/glyph journeys; bilingual guides document source/copy/cache bounds and whole-source examination.
- Caller-owned shared font retention across portable and eligible CoreText captures, with simultaneous face/capture/scope budgets including reservations, retirement and residual cleanup charges; independent consumer owners survive eviction and scope closure. Bilingual guides and a separate opt-in public-consumer measurement document accounting, bounded admission work and known native resource ownership.
- SVG-in-OpenType painted paths and rectangles may reference a preceding local, exact schema-3 `userSpaceOnUse` `clipPath` with one self-closing static path or sharp-cornered rectangle child. Definition and child transforms compose per reference as `T * C * P`, preserving child-paint spaces under an outer `PathClip` intersection. Authored operations consume the shared source budget once; each generated clip independently obeys node, reference, path, clip, depth, paint-visit, and outline limits without a generated `Transform` charge. Reached validation precedes singular or zero-area clip omission, errors remain typed, and acquisition stays atomic with ordered profile fallback.
- SVG-in-OpenType painted paths and rectangles accept finite unitless or percentage `fill-opacity`, defaulting to opaque and clamped to `0..1`. Translucent solids normalize under a shape `PathClip`; gradients derive immutable per-reference stop opacities without changing reusable definitions. Zero opacity validates reached geometry, paint capabilities and resource bounds before omission; unsupported group/CSS opacity and paint attributes on clip children remain rejected.
- SVG-in-OpenType paths may now reference preceding local `userSpaceOnUse` linear or concentric radial gradients. Path geometry remains under the active group transform `T`; linear paint points use `T * G`, while non-solid radial paint retains the existing single `T * G` transform node. Empty and intrinsically solid definitions keep the established clipped normalization, reference-time reuse remains bounds-independent, and path references to `objectBoundingBox` gradients stay typed unsupported even before solid reduction or singular-transform omission. Existing profile capabilities and paint-graph budgets remain authoritative, and failures publish no partial graph.
- SVG-in-OpenType gradients now additionally accept explicit finite unitless `userSpaceOnUse` coordinates on rectangles. Linear geometry uses `T * G` without a graph transform; non-solid concentric radial geometry retains its absolute circle below one existing `Transform` node and one transform-budget entry carrying `T * G`, while each rectangle clip remains under `T` alone. Rectangle-relative gradients preserve `T * B * G`. Linear `x1`/`y1`/`x2`/`y2` and radial `cx`/`cy`/`r` are required in absolute user space, with omitted radial `fx`/`fy` inheriting the accepted center. Viewport-dependent percentages/defaults and unknown coordinate spaces remain typed unsupported; malformed absolute numbers and negative non-zero radii remain invalid data. Coordinate validation precedes empty, one-stop, and zero-radius reductions, profile fallback remains ordered and all-or-nothing, and reuse resolves geometry under each reference transform independently of rectangle bounds.
- Portable `PaintGraphProfile` schema 3 with explicit linear-sRGB or sRGB space and premultiplied or unpremultiplied alpha interpolation, plus bounded `PathClip` nodes charged against path and clip limits; static COLR remains premultiplied while renderers remain consumer-owned.
- The bounded SVG-in-OpenType subset now accepts static `defs` definitions containing `linearGradient` or concentric `radialGradient` paint servers applied to later `rect` elements. It normalizes strict SVG numbers, unpremultiplied alpha interpolation, complete repeat/reflect periods, reached-stop accounting, and all six bounded SVG 1.1 transform functions: ordered `translate`, `scale`, `rotate(angle)`, `rotate(angle cx cy)`, `skewX(angle)`, `skewY(angle)`, and six-coefficient `matrix` syntax normalize into schema-3 linear or radial paint. Rotation and skew angles use SVG degrees; finite negative and wrapped angles remain valid. Authored rotation centers are preserved, exact quadrant rotations and zero/±45-degree-equivalent skews avoid trigonometric residue, and every complete function call consumes one authored transform operation. Skews use the 180-degree tangent period and preserve positive determinant orientation; exact odd-quarter-turn asymptotes, lexically non-zero angles decoded to zero, non-finite tangents, malformed lists, and numerically unrepresentable composition are invalid data. Gradient transforms compose after object-bounding-box geometry, share the authored SVG transform budget, affect only gradient geometry, and reject singular mappings as unsupported. Singular group transforms contribute no filled path or rectangle paint, while numeric rank loss or determinant-orientation inversion is invalid data. Radial geometry uses an explicit bounded transform, while one-stop and zero-radius cases reduce to solid paint under the rectangle `PathClip`. Schema-1 solid SVG keeps its historical node/depth policy without a paint-visit budget.
- SVG-in-OpenType render assets now accept bounded raw UTF-8 and single-member gzip document transport, publish only immutable portable paint IR, and report typed failures for malformed transport and encoded or decoded byte limits.
- Portable `PaintGraphProfile` schema 2 for static COLR version 1 and CPAL 0/1, including resolved palette and foreground colors, gradients, affine transforms, clips, all composition modes, bounded certification, per-glyph fallback, resource limits, and retained-asset handoff; schema 1 remains compatible with existing COLR version 0 and solid-only SVG-in-OpenType routes.
- Opt-in public font-asset handoff and four-worker resolution measurements, with stage percentiles and an observational Apple M2 Max reference outside functional checks.
- Immutable layouts can now be paired with an explicit closable handle that atomically retains all certified font roots and hands independent assets to delayed renderers.
- Structured portable font materialization cache budgets for estimated retained bytes, decoded pixels, native bytes and native allocations, enforced atomically per face and per catalog with global LRU ordering; preserves the historical byte-only constructor and observable glyph results. Native charges remain zero until a native route owns cacheable resources.
- Reproducible opt-in measurement of cold and warm portable TrueType editor stages for preparation, text mapping, metrics, outlines, and detached render assets.
- Exact region-chain composition through `org.graphiks:kalligraphie`: immutable application-supplied `FlowRegion` geometry with exclusions and bounded refinement, logical lines distributed into geometric `LineFragment` values without restarting BiDi or splitting clusters and inline objects, deterministic fragmentation relaxation diagnostics, identity-attested `FlowContinuation` reuse, and incremental forward rematerialization with explicit unmaterialized coverage.
- Advanced typography and derived content through `org.graphiks:kalligraphie`: typed `GlyphProvenance` for direct, derived, and synthetic glyphs, soft and automatic hyphenation (versioned pattern service with digest-verified `hyph-en-us` data and structured diagnostics), inter-word / inter-character / kashida justification, tab stops with START/END/CENTER/DECIMAL alignment and synthetic leaders, ellipsis truncation (`INLINE_START`, `MIDDLE`, `INLINE_END`) with explicit hidden source ranges, inline objects for `U+FFFC` with caret/selection/hit-testing semantics, and final-glyph recertification after every transform.
- Vertical paragraph writing through `org.graphiks:kalligraphie`: `VERTICAL_RL` and `VERTICAL_LR`, Unicode 16.0 UTR #50 orientation, HarfBuzz top-to-bottom shaping with `vert`/`vrt2`, OpenType `vhea`/`vmtx` metrics with explicit deterministic fallback, physical editing geometry, and incremental reflow parity.
